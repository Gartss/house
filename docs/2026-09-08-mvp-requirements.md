# House 买房首版需求与页面方案

日期：2026-09-08。本文作为首版开发依据；已确认范围与下文建议的实现规则分开记录。已进入应用开发，本地页面正在按用户反馈迭代；尚未完成线上交付。

## 1. 已确认范围

个人买房使用，首版处理二手房，不包含租房。核心是可编辑房源表格和价格走势图。

当前优先完成 MVP：房源截图录入与核对、可编辑房源表格、单套房报价历史和走势图。小区行情已由用户明确延后，第 9 节仅保留后续功能备忘，不属于首版开发、页面或验收范围。

支持收藏列表截图批量录入，支持多张详情截图补充同一套房。识别后先核对再保存，缺失信息留空，保留原图和历史报价，不自动合并不确定的房源。本地开发资料全部保存在 House 项目目录内，未经授权不对外上传。

运行载体已明确为手机端网页，外出时通过移动网络也能打开，不依赖个人电脑持续开机或同一Wi-Fi。下述线上保存和登录为实现建议；尚未选定部署服务，也未授权向某个具体服务上传截图。首版不要求原生App或离线使用。

## 2. 首版字段建议

表格默认仅展示常用比较字段，其他字段在详情中编辑，避免横向堆叠全部信息。

| 字段                                         | 展示位置     | 录入与显示规则                                                 |
| -------------------------------------------- | ------------ | -------------------------------------------------------------- |
| 小区/地址                                    | 主表         | 按截图原文提取；无法区分地址与小区时保留原文待核对             |
| 最新记录总价（万元）                         | 主表         | 表示最新有明确日期的报价，不能称为已验证的实时价格             |
| 单价（元/㎡）                                | 主表         | 优先显示页面单价；由总价和面积计算时标记“计算值”，保留页面原值 |
| 建筑面积（㎡）                               | 主表         | 不与套内面积混用                                               |
| 户型                                         | 主表         | 保留几室几厅，缺少卫生间数不补写                               |
| 楼层                                         | 主表         | 楼层段、具体层数、总层数分别保存；“中楼层”不能换算成具体几楼   |
| 朝向                                         | 主表         | 原文提取，多朝向可并存                                         |
| 装修                                         | 主表         | 未提供留空；宣传标题可留在原文中，不直接当作已核实属性         |
| 报价日期                                     | 主表         | 优先读取截图日期；未读到时默认填写导入当天，可在核对页修改     |
| 备注                                         | 主表         | 用户可编辑看房感受等内容                                       |
| 区域、楼栋、房号                             | 详情         | 未知可空，不从小区或图片推断                                   |
| 建成年份、电梯、建筑类型、房屋用途、产权性质 | 详情         | 按页面明确属性提取                                             |
| 房源核验码、来源平台、链接                   | 详情         | 核验码按文本存储；未提供的平台或链接不猜测                     |
| 原始标题、标签、动态原文                     | 详情         | 与结构化属性分开，保留来源截图                                 |
| 带看、关注数                                 | 详情         | 可选字段，保存统计口径及当次记录；“新增关注”不等于关注总数     |
| 原始截图                                     | 详情与核对页 | 一套房可关联多图，一张列表图可关联多套房                       |

内部使用独立房源编号，不以“小区+面积”作为唯一身份。资料允许不完整，但保存前需由用户确认，并至少有可辨识的小区/地址或自定义名称。

## 3. 截图导入与核对流程

1. 点击“导入截图”，选择一张或多张图片，识别为房源列表或房源详情；识别错误可手动调整类型。小区行情截图不在首版支持范围，不生成房源记录。
2. 列表图拆分为多条待核对记录；详情图可由用户指定属于同一套房。保存前均为草稿。
3. 手机核对页集中展示全部截图的待核对表格：一套房一行、同类字段一列，直接编辑单元格。每行可查看对应原图；支持逐行勾选和全选，默认不勾选，核对后一次保存所选行。截断或不确定字段留待核对，缺失值留空。
4. 每条记录选择“新增房源”或“补充已有房源”。核验码一致可优先提示，其他相似字段仅提供候选，最终由用户决定。
5. 补充资料时显示原值与新值；冲突字段由用户选择，不用空值覆盖已有资料。报价变化以新增价格记录保存。
6. 核对报价日期；截图未读到日期时默认填写导入当天，并可逐条修改。
7. 保存前校验整个所选批次；任何所选行有错误都不部分提交。成功后所选行进入正式房源，未选行及其修改继续保留为草稿；草稿保留报价、日期、备注与关联目标。识别失败时允许看原图手工填写。

重复导入同一文件时提示已导入并允许查看关联记录，不能静默生成重复房源。再次记录相同价格也允许保存为新的观察记录，但重复提交同一操作不得产生两次写入。

## 4. 页面布局

### 主页面：手机房源表格

按2026-09-08用户反馈：去掉“我的房源”“看房记录”等占空间的重复标题，保留紧凑工具区与搜索筛选。主视图直接展示表格，一套房一行，小区/地址、总价、单价、面积、户型、楼层、朝向、装修、报价日期、备注分别固定为列。支持横向滚动，固定选择列和小区列便于定位；点击小区名称进入编辑和价格详情。已选房源仍以同样列顺序比较。

“新增”和“相册导入”置于底部悬浮操作区，适配手机安全区域，内容预留底部空间。保留搜索、排序、筛选及已归档入口。

备份用于另存完整资料与原图、恢复用于补回备份中的资料；日常使用不必操作。导出、恢复及说明收进右上角“更多”菜单，不占主表底部或主操作区。

不添加首页仪表盘、推荐信息流或地图。首次打开显示导入和手动新增入口，无示例数据冒充个人房源。

### 房源详情页

手机采用独立详情页，从上到下：名称及最新记录报价 → 价格走势图 → 历史价格明细及“记录报价” → 房屋属性与备注 → 来源截图。返回列表保留筛选与浏览位置。

### 导入核对页

统一核对表覆盖全部待处理截图，每行直接修改字段、填写报价和日期、选择“新增房源”或具体已有房源。扩展列按需显示，原图可展开或单独放大。底部悬浮“保存草稿”和“保存已核对N套”。离开时提示未保存修改；默认不勾选，只有用户选中的行进入正式资料。

## 5. 价格历史规则

每条价格记录保存：所属房源、金额、报价日期（可空）、记录创建时间、价格类型、来源截图及备注。首版以挂牌报价为默认候选，用户核对后保存；截图不能据此推断成交价。

走势图横轴为报价日期，纵轴为总价（万元），只使用已确认且日期明确的记录。只有一个点时显示单点并提示继续记录；未知日期记录列在明细中等待补充。不同价格类型不混连为同一条曲线。同日多次记录保留明细顺序，不捏造具体时刻。

“昨天降价 3 万”等保存为动态原文，不从相对描述推算历史日期；截图没有明确日期时使用导入当天。“近半年未调价”不能生成半年曲线。

主表编辑总价时打开“记录报价”表单，新增历史而非覆盖旧值。修正录入错误需要明确标记为更正并保留更正前值；删除记录建议采用可恢复方式。

## 7. 首版验收

- 导入图 1，可核对并保存 4 条独立房源，每条均能查看同一来源图。
- 导入图 3、4，可组合核对成 1 套房；中楼层仍保留为楼层段，具体楼层为空。
- 房源样例不提供完整日期时，报价日期默认填写导入当天，用户可在保存前修改。
- 房源和待核对内容均为行列表格；同类字段在同列。可编辑、排序、组合筛选，并清除筛选恢复完整列表。
- 批量核对：默认不选中；一次可保存多行；未选行的修改及报价日期仍在草稿中；任意所选行错误时整个批次不提交。
- 页面顶部无重复大标题，新增和相册导入位于底部悬浮区，备份仅保留次级菜单入口。
- 为已有房源追加一个测试报价后，两次记录均存在，日期明确时走势图显示相应点位；测试数据不得混入真实房源。
- 补充详情不覆盖已有非空字段，冲突时可逐项选择。
- 识别失败可手动录入；取消或重试不会生成已保存的重复房源。
- 关闭并重新打开后资料和截图仍存在；备份恢复能还原房源、价格历史及截图关联。
- 手机关闭Wi-Fi、使用移动网络时仍能登录访问、导入截图、核对保存和查看走势；无需开发电脑开机。
- 未登录不能读取房源或原图，包括直接访问数据接口与图片地址；退出后不再展示私人数据。
- 弱网或上传中断时显示明确状态并支持重试，不显示虚假保存成功，不重复创建记录。

## 8. 实施顺序与待决策

建议先验证手机访问、私有存储、登录与识别方案；实现手机列表、对比表、详情、手动录入和历史价格保存，再接入截图识别及核对流程，最后验证移动网络访问和备份恢复。

技术框架、部署服务、线上持久化方式及截图识别引擎尚未确定。建议采用HTTPS手机网页、单用户登录、私有数据库和图片存储，保证出门可访问；仅依赖浏览器缓存不足以满足保存与备份需求。线上部署副本的存放位置属于新增待确认事项，本地代码、文档、测试资料和备份仍保存在House目录。先用非敏感测试数据准备可审阅的部署方案，明确目的地、费用和访问保护，再处理实际资料上传。识别方案须测试手机截图效果，第三方识别服务接收截图的授权与网页托管分开处理。

### 保存和核对

新增小区档案，与房源建立关联。小区行情独立保存，每条记录包含小区编号、统计月份、指标类型（挂牌均价/成交均价）、数值、单位、来源平台（未知可空）、来源截图、录入时间和核对状态。小区资料和在售数量的观察记录保留各自来源，不混为单套房属性。

导入后核对小区身份、统计月份和两种均价。月份不足以确定年份时留待补充；本图可依据“26.08”给出年份候选，但不能根据导入当天自动推断。已有同小区、同月份、同指标记录时显示来源及新旧值；相同数据不重复绘点，冲突需用户选择采用版本，保留旧值与来源。不同来源的统计口径不自动合并。

### 页面与走势

主页面增加轻量的“房源 / 小区”切换，小区页仍以表格为主：小区、区域、最新统计月份、挂牌均价、成交均价。点击小区打开详情侧栏，展示两种均价的走势、可编辑月度明细、基础资料、关联房源和来源截图；房源详情中的小区名称也可进入这里。

小区走势图按月展示，纵轴为元/㎡，挂牌与成交均价分别绘制并明确图例。只有一个已确认月份就显示单点，不生成历史曲线；缺少月份时保留缺口，不插值。仅凭截图折线位置无法得到精确月度数值，未标出的历史点不录入。后续可通过更多带数值的截图或手工记录逐月积累。

单套房总价曲线仍以万元为单位，独立展示。小区均价用于提供背景，不直接认定某套房低估或高估，也不视作该套房成交价。

## 手机对比与删除更新（2026-09-08 用户确认）

本节取代此前手机端全字段横向宽表的方案。

- 房源首页保留一套一行，切换“价格 / 户型 / 楼层装修”字段组；同类数据同列对齐。房源勾选框常驻。切换主题保留筛选和选择；表头可按总价、截图单价、面积升序排列。
- 至少勾选两套进入专门对比页：一套固定为基准，另一套通过下拉或上一套/下一套切换。指标纵向排列，房源表头固定，支持只看差异。缺失值保持空缺标记，不推断。
- 对比页叠加两套有日期的报价走势，支持总价/计算单价切换。计算单价使用当前建筑面积，明确区别于截图单价；缺少日期或面积时提示。
- 房源详情竖向编辑；待核对按价格、户型、楼层装修、补充资料分组，手机每套竖向填写，保留批量核对保存。
- 详情可删除单套，列表勾选后可批量删除，待核对可删除所选误识别记录。操作前显示确认提示；已保存房源删除包含其报价历史，不能直接撤销，原始图片文件保留，不删除其他房源共用图片。
- 后端仅对请求明确列出的房源允许整体删除；普通保存仍禁止删除房源或改写已有报价。沿用版本冲突、身份隔离及失败后保留界面的保护。
- 删除不清理对象存储原图；历史备份仍可能包含被删记录，恢复旧备份可重新补回。图片文件彻底清理不属于此次功能。

## 新增需求待办（2026-09-08）

状态：已记录，待开发。跟踪入口为开发计划表“新增需求待办”。

### 1. 区域与板块

房源信息增加“区域”“板块”，支持编辑和截图核对；筛选包含区域、板块，并可与已有条件组合；对比表中显示对应字段。区域与板块分开保存，板块归属区域；缺失信息留空，旧数据保持兼容。

### 2. 小区成交价

支持不包含房源详情、只有小区成交价的独立截图。按小区保存成交价，记录单位、统计时间、来源截图，识别后核对；缺少小区信息时手动指定。相同小区关联的房源展示对应成交价，避免重复填写。不将小区成交价混入单套房报价历史；不猜测是均价、单笔成交价或对应月份，按截图明确的口径核对。更新保留历史，不静默覆盖或合并不确定小区。

验收：一张核对后的成交价截图能关联到对应小区的多套房源，其他小区不受影响；后续更新可追溯原图及历史。此项是既有第9节小区行情备忘的独立待办，不意味着实施完整小区行情页。

### 3. 户型图实际面积与得房率

每套房源支持上传户型图，读取各房间面积，展示可编辑的房间面积明细；计入房间的面积直接合计为实际面积，在其旁显示得房率。修改房间面积或计入状态时实时重算。得房率采用“实际面积 ÷ 建筑面积 × 100%”，建筑面积沿用房源原字段，不被计算结果覆盖。

验收：修改任一房间面积后合计与得房率同步变化；缺少建筑面积时不计算比例；房间名称未识别时标记待核对，但已读到且勾选计入的面积仍进入实时合计。保留户型图来源。计算值是当前房间明细的合计，不自动等同于测绘套内面积。

### 4. 到地铁站与商圈的实际路线距离

状态：待开发。依据小区地址定位，查找附近地铁站与商圈，通过路线规划获取步行或驾车距离，在房源中展示目的地、距离和对应出行方式。不用两点直线距离代替实际路线距离，也不把直线距离最近的目的地直接认定为步行最近。

实现边界：

- 起点优先使用经核对的小区可通行出入口，地铁终点使用具体出入口，商圈终点使用明确的入口或代表地点；支持用户核对修改，避免地图中心点造成误差。
- 地址不足、重名或定位不确定时先核对，不能自动选择不确定的小区。
- 步行、驾车分别计算并标注；道路通行条件与出入口不同可能导致距离不同。保留路线查询时间和目的地，支持重新计算。
- 路线服务不可用或没有可通行路线时显示暂无法计算，不回退为未标注的直线距离。
- 实施前验证地图/路线服务的覆盖、调用额度、费用、访问配置，以及发送给服务方的地址数据范围；当前仅记录需求，不发送地址或接入外部服务。

验收：同一房源能查看附近地铁站、商圈的路线距离及出行方式；修改起终点后重新计算；无路线时不显示虚构数值。具体服务选型留到实施阶段。
